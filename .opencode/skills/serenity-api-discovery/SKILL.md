# Serenity API Discovery

Use this skill when the user wants to discover, analyse or document
business APIs used by a web application.

Use Playwright MCP to navigate through the real application and inspect
the network traffic generated by the business flow.

Do not implement API automation unless explicitly requested.

## Main objective

Discover the APIs involved in a business flow and prepare the information
required to automate them later using:

- TypeScript
- Serenity/JS
- Screenplay Pattern
- Cucumber
- @serenity-js/rest
- pnpm

## Discovery workflow

Before starting:

1. Understand the business flow requested by the user.
2. Identify the start and end point of the navigation.
3. Use Playwright MCP to explore the application.
4. Inspect network requests while executing the flow.
5. Identify only business-relevant APIs.

## Ignore static traffic

Do not include requests related only to:

- images
- fonts
- CSS
- JavaScript bundles
- favicons
- analytics
- advertising
- telemetry

unless the user explicitly requests them.

## For each relevant API capture

Identify:

- business purpose
- HTTP method
- endpoint
- path parameters
- query parameters
- relevant request headers
- request body structure
- response status
- response body structure
- dependency on previous requests
- data obtained from previous responses
- authentication requirements

## Authentication and security

Never expose, store or hardcode real:

- passwords
- access tokens
- refresh tokens
- cookies
- session IDs
- API keys
- authorization headers
- personal information

If authentication information is discovered:

- identify the authentication mechanism
- indicate that authentication is required
- redact the secret value

Example:

Authorization: Bearer [REDACTED]

Do not copy real credentials into source code.

## Request headers

Do not blindly reproduce all browser headers.

Identify only headers that appear relevant to the API contract.

Examples may include:

- Content-Type
- Accept
- Authorization
- custom business headers

Ignore browser-specific headers unless the API requires them.

## API dependencies

Identify dependencies between API requests.

Example:

Authentication
    ->
Availability
    ->
Flight selection
    ->
Bundles
    ->
Passengers
    ->
Seat map

If one API requires data returned by another, document it.

Example:

POST /availability
returns journeyKey

journeyKey
is required by

POST /selection

## Business grouping

Group discovered APIs by business capability.

Example:

### Authentication

APIs related to login or session creation.

### Flight search

APIs related to:

- stations
- routes
- dates
- availability

### Flight selection

APIs related to:

- journey selection
- fares
- bundles

### Passengers

APIs related to passenger data.

### Seats

APIs related to:

- seat map
- availability
- seat selection

## Playwright MCP

Use Playwright MCP to:

- navigate the real application
- execute the requested business flow
- inspect network requests
- understand request dependencies
- inspect request payloads
- inspect response structures
- identify dynamic values

Do not use MCP traffic blindly.

Analyse whether each request is relevant to the business flow.

## Data analysis

Identify:

- static request values
- dynamic request values
- IDs generated during the flow
- values reused between requests
- environment-dependent values

Indicate when a value should later become:

- test data
- environment configuration
- runtime variable
- response-derived value

## Output

At the end of discovery provide:

### Business flow

Describe the flow explored.

### API inventory

For every relevant API show:

- purpose
- method
- endpoint
- request
- response
- expected status
- dependencies

### Dependency map

Show the order in which APIs interact.

### Authentication

Describe the authentication mechanism without exposing secrets.

### Test data

Identify the data required to automate the APIs.

### Recommended automated scenarios

Suggest API scenarios such as:

- successful request
- invalid request
- missing mandatory field
- invalid authentication
- business validation
- boundary conditions

### Risks

Identify issues such as:

- dynamic tokens
- session dependencies
- anti-bot mechanisms
- rapidly changing IDs
- undocumented API behaviour
- external service dependencies

### Automation readiness

Indicate which APIs are ready to automate with Serenity/JS REST.

Do not generate automation code unless explicitly requested.
